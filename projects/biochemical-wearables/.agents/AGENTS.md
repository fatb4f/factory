# Biochemical wearables monitor

Select `projects.biochemical-wearables.upstream-monitor` from current Factory main. Read the shared worker CUE and procedure, every CUE file in `profiles_biochemical_wearables`, then the local report template. Follow the prior `latest.json` to its sealed evidence and trace earlier records for the same device generation, study or technology. When the pointer is absent at initial setup, establish the baseline from records retrieved during this run. An unreadable or inconsistent existing pointer is a comparison gap.

## Acquire and compare

1. Revisit the seed devices and unresolved gaps. Search the scholarly discovery channels for new human studies, validation, replication and retractions. Search for new products and successor models outside the seed list. Follow index and news leads to the primary paper, technical manual, platform specification or regional offer. Record the discovery query and time window in the report, and use coverage gaps for channels that could not be checked.
2. Identify the original source, its channel, exact record, version or retrieval date, and passage supporting each claim. Preserve study DOI, model or SKU, app or firmware version and market when available. Group preprints with their final paper and syndicated stories with the original release. Two distributors quoting one announcement contribute one origin. Keep competing evidence and revised results visible.
3. Apply the profile's trending, emerging and market criteria. State the dated change from the comparison window. Track research milestones separately from commercial status and check that validation applies to the same model, output, population and operating conditions. For study performance, retain the reference method, sample size, units and reported error or agreement interval when available.
4. For sweat measurements, record collection site, induction or activity, warm-up and wetting requirements. Distinguish concentration, local flow, estimated whole-body loss and downstream inference. Keep temperature site and units explicit. Record a sweat-to-blood or other systemic interpretation only to the extent supported by a matching paired comparator. For fatigue, stress or heat strain estimates, identify inputs and evaluation conditions. Preserve the original units alongside any unit conversion.
5. Check the seller, model, region, dated offer, currency, stock or preorder, shipping destination and consumable costs. Check Canadian fulfillment explicitly. Scope each seller record to the model and markets supported by its text. Keep distinct offers under separate stable item IDs when sellers disagree within one market. For telemetry, record the owner-accessible path, Android compatibility, raw or processed fields, documented BLE protocol, export format, API and access conditions. Record sensor sampling, app refresh and exported row cadence separately. A public spreadsheet of estimated losses establishes only those fields. Mark missing documentation as unknown and say where it was sought.
6. Assess use in active exercise, at rest and in owner-operated data collection against the documented evidence. Surface relevant failure cases such as insufficient sweat, pooling or lag, interpolation, cloud access ending and an offer for a different hardware revision. Count distinct origins, models and studies. For any coverage or access fraction give its numerator, denominator and unknown count.

## Publish

Render the report with the fixed template and a short summary of material changes and coverage gaps. Use the initial baseline, material changes or changed material gaps to trigger publication. A completed comparison with no change returns `no_change`. A failed query leaves its channel unresolved.

Use `#RunEvidence`, `#Manifest` and `#Pointer` from the selected profile. Write `report.md`, `summary.md` and `evidence.json` under `projects/biochemical-wearables/upstream-monitor/runs/<run_id>/`. Seal their exact Git blob SHAs in `manifest.json`, then update the sibling pointer `projects/biochemical-wearables/upstream-monitor/latest.json`. Vet the concrete JSON against each matching definition with CUE, and verify the pointer path, IDs, revisions and artifact hashes together. Publish through the repository workflow. If the previous pointer changed meanwhile, compare against the new run before publishing. Preserve the last sealed run when acquisition, vetting or publication cannot support a new one. Record corrections in a new run with lineage.
